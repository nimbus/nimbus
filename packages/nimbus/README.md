# @nimbus/nimbus

The first-party JavaScript/TypeScript SDK for talking to a
[Nimbus](../../README.md) backend from the browser, a React app, or a server.

Nimbus is a Convex-compatible backend server. This package is the **native**
client surface — written against Nimbus's own naming (`NimbusClient`,
`NimbusProvider`, `useNimbus`). If you are porting an existing Convex app and
want a drop-in `convex` import instead, use the [`convex`](../convex/README.md)
compatibility package, which is a thin wrapper around this one.

## Entry points

This package ships several subpath exports so you only pull in what a given
environment needs:

| Import | Use it for |
| --- | --- |
| `@nimbus/nimbus` | The high-level `Nimbus` SDK client for Nimbus-specific resource APIs; the current landed slice owns service lifecycle/status |
| `@nimbus/nimbus/react` | React hooks and providers (`NimbusProvider`, `useQuery`, `useMutation`, `useAction`, `usePaginatedQuery`) |
| `@nimbus/nimbus/browser` | The framework-agnostic `NimbusClient` (reactive WebSocket queries + HTTP mutations/actions) |
| `@nimbus/nimbus/server` | Types and builders for authoring backend functions (`query`, `mutation`, `action`, schema/validator types) |
| `@nimbus/nimbus/values` | The validator builder `v` and value types (`GenericId`, `Validator`, `Infer`) |
| `@nimbus/nimbus/transports/rest` | The explicit low-level REST + subscription clients (`NimbusRestClient`, `NimbusSubscriptionClient`) for transport-level callers |

## Usage

### React

```tsx
import { NimbusReactClient } from "@nimbus/nimbus/browser";
import { NimbusProvider, useQuery, useMutation } from "@nimbus/nimbus/react";
import { api } from "../convex/_generated/api"; // generated by `nimbus codegen`

const client = new NimbusReactClient(import.meta.env.VITE_NIMBUS_URL);

function App() {
  return (
    <NimbusProvider client={client}>
      <Messages />
    </NimbusProvider>
  );
}

function Messages() {
  const messages = useQuery(api.messages.list, { channel: "general" });
  const send = useMutation(api.messages.send);

  if (messages === undefined) return <p>Loading…</p>;
  return (
    <button onClick={() => send({ channel: "general", body: "hi" })}>
      Send ({messages.length})
    </button>
  );
}
```

For authenticated apps, wrap the tree in `NimbusProviderWithAuth` and pass a
`useAuth` hook that returns `{ isLoading, isAuthenticated, fetchAccessToken }`.

### Plain JavaScript (no React)

```ts
import { NimbusClient } from "@nimbus/nimbus/browser";

const client = new NimbusClient("https://my-deployment.nimbus.dev");

// One-shot read
const messages = await client.query(api.messages.list, { channel: "general" });

// Reactive subscription
const unsubscribe = client.onUpdate(
  api.messages.list,
  { channel: "general" },
  (messages) => console.log("new value", messages),
);

// Writes
await client.mutation(api.messages.send, { channel: "general", body: "hi" });
await client.action(api.email.sendReceipt, { to: "a@b.com" });
```

### Authoring backend functions

Backend functions live in your app's source root (`nimbus/` or `convex/`) and
are authored against `@nimbus/nimbus/server` + `@nimbus/nimbus/values`:

```ts
import { query, mutation } from "@nimbus/nimbus/server";
import { v } from "@nimbus/nimbus/values";

export const list = query({
  args: { channel: v.string() },
  handler: async (ctx, { channel }) => {
    return await ctx.db
      .query("messages")
      .withIndex("by_channel", (q) => q.eq("channel", channel))
      .collect();
  },
});

export const send = mutation({
  args: { channel: v.string(), body: v.string() },
  handler: async (ctx, { channel, body }) => {
    await ctx.db.insert("messages", { channel, body });
  },
});
```

Run `nimbus codegen --app <dir>` to produce the `_generated/api` references used
by the client above. Codegen runs in-binary; `@nimbus/codegen` is embedded in
the `nimbus` binary and is not installed into your app.

### Nimbus Service Lifecycle

```ts
import { Nimbus } from "@nimbus/nimbus";

const nimbus = new Nimbus({ tenantId: "demo" });

await nimbus.services.start({ name: "db", waitUntil: "ready" });
const db = await nimbus.services.get({ name: "db" });
await nimbus.services.restart({ name: "db" });
await nimbus.services.stop({ name: "db" });
```

Service lifecycle is explicit: `start`, `stop`, and `restart` perform lifecycle
actions, while `get` returns status/info. Sandbox and session resource APIs are
not exposed from this SDK until the matching server routes land.
