# DA9 proof — network-bind guardrails (NB1 + NB2)

Captured 2026-05-20 against the debug build at target/debug/nimbus.
Refreshed post-audit to reflect the two-stage gate split: `--host` /
opt-in mismatch fails fast before codegen (stage 1), and the token-
freshness tripwire runs after the admin token is loaded (stage 2).

## `nimbus start --help` advertises the `--allow-network` opt-in

$ nimbus start --help | grep -A2 'allow-network\|--host '
      --host <HOST>
          Host interface to listen on. Defaults to loopback for local safety

      --allow-network
          Opt-in to binding on a non-loopback interface. Without this flag, `nimbus start` refuses any `--host` that resolves outside the loopback range. With the flag set, the daemon additionally requires that the local admin token has been rotated within the staleness window (see `nimbus auth rotate-admin`).

test result: ok. 8 passed; 0 failed; 0 ignored; 0 measured; 499 filtered out

The matrix verifies, across the two stages:

Stage 1 — `ensure_host_opt_in(host, allow_network)`:
  - Loopback hosts (127.0.0.1, ::1, localhost) bypass the gate.
  - Non-loopback bind without --allow-network exits with the refusal +
    opt-in hint message.
  - Non-loopback bind with --allow-network proceeds past stage 1 and
    falls through to the freshness check.

Stage 2 — `ensure_admin_token_fresh_for_public_bind(host, token, now)`:
  - Loopback hosts (127.0.0.1, ::1, localhost) bypass the gate.
  - Non-loopback bind with a never-rotated admin token exits with the
    tripwire pointing at `nimbus auth rotate-admin`.
  - Non-loopback bind with a stale rotated_at also trips, with the same
    hint.
  - Non-loopback bind with a fresh rotated_at is allowed to proceed.
  - Unparseable rotated_at strings are treated defensively as stale.

Splitting the gate this way means stage 1 fires in `run_start_command`
before `run_codegen_preflight` (boot.rs), so a typo'd `--host` (or a
forgotten `--allow-network`) fails fast without paying codegen cost.
The freshness check still runs after `load_or_create_local_admin_token`.

The new tests assert:
  - Offline rotation sets `rotated_at` to a parseable RFC 3339 timestamp
    and the record reports fresh inside the 30-day window.
  - Legacy on-disk records (no `rotatedAt` field) still load and surface
    as stale to the bind tripwire.

## `nimbus auth rotate-admin` is locked in by the auth-dx grep gate

$ bash scripts/verify-auth-dx-gates.sh
auth-dx microcopy grep gates clean

The script pins `name = "rotate-admin"` in `auth.rs` and the
`nimbus auth rotate-admin` recovery hint in `network_bind.rs`, so a
rename of the subcommand fails CI rather than silently un-anchoring the
DA10 agent-auth contract doc that references it.
