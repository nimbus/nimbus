# DA4 proof — `nimbus start` first-boot launch URL banner (H5)

## Marker shape

The first-boot signal is a stamp file at
`<control-data-dir>/.nimbus-init-stamp`. It is written *after* the
banner emits, so a Ctrl-C between the listener binding and the stamp
write still surfaces the banner on the next boot. The marker is in
the control data dir (not LocalServerPaths) so a user blowing away
`--data-dir` triggers a fresh welcome.

## Wiring (see crates/nimbus-bin/src/start/boot.rs)

1. Snapshot `is_first_boot_run = is_first_boot(&compose_control_data_dir)`
   *before* `Service::new_with_persistence_config` runs, so the marker
   isn't poisoned by Service initialization touching the data dir.
2. After binding the listener and acquiring the discovery lease, spawn
   `first_boot::spawn_first_boot_announce(...)` only when
   `is_first_boot_run` was true.
3. The spawned task waits for `/ui/auth` to answer, mints a launch
   ticket against the local server, prints the H5 banner to stderr,
   then writes `.nimbus-init-stamp`.
4. On shutdown, the join handle is aborted so the announce task does
   not outlive the daemon if /health never came up.
