# JS Lane Spec — CO13 (convex client dedup), CO14 (SDK barrel split), DE16 (protobuf gen)

Design authority: `architecture-review-2026-07-plan.md` rows + the
2026-07-07 JS-lane inventory. Package scope: `packages/convex`,
`packages/nimbus`, `packages/firebase` (+ gitignore/CI wiring for
DE16). Pre-launch: breaking changes preferred. The CLAUDE.md rule
governs CO13: `packages/nimbus` is canonical; `packages/convex` must be
thin adapters/re-exports — `browser.ts` is the LAST file still
copy-forwarding parallel logic.

## Facts this rests on (inventory)

- `packages/convex/src/browser.ts` (589 lines): three classes extending
  Nimbus bases — `ConvexHttpClient extends NimbusHttpClient` (:161, no
  onUpdate), `ConvexClient extends NimbusClient` (:273),
  `ConvexReactClient extends NimbusReactClient` (:432). The six
  invocation methods (query/mutation/action/paginatedQuery/
  scheduleAfter/scheduleAt) are byte-identical across classes: declare
  Convex-branded overloads → `super.<method>(coerce*Reference(x), args)`.
  `onUpdate` duplicated across the two live clients. The genuine
  value-add is module-level coercion (:59–159): `anyApi` proxy,
  `coerce{Query,Mutation,Action}Reference`,
  `assertNamedLiveQueryOptions`, `withConvexDeploymentUrlCheck`
  (renames `skipConvexDeploymentUrlCheck` → `skipDeploymentUrlCheck`).
- `packages/nimbus/src/browser.ts` bases: `NimbusClient` (:96) holds the
  real implementations; `NimbusReactClient extends NimbusClient {}` is
  empty (:757); `NimbusHttpClient` from `./http-client.ts`.
- Other convex entry files are already pure re-exports/thin wrappers
  (values.ts, internal/shared.ts, server.ts, react.ts).
- `packages/nimbus/src/index.ts` (1,003 lines) is a MONOLITH, not a
  barrel: :13–432 inline control-plane types (NimbusCredential,
  NimbusClientOptions, Service/Sandbox/Session type families), :433–697
  `Nimbus` class (only exported class; sub-managers `NimbusServices`
  :495 / `NimbusSandboxes` :613 / `NimbusSessions` :656 are unexported),
  :699–1003 private helpers (`createDefaultRestClient` credential/
  endpoint discovery, param builders, wait loops). package.json exports
  is a flat map; `.` already IS the control-plane surface.
- `packages/firebase/src/gen/**`: 25 tracked files, ~19.1k lines,
  generated by `codegen-protos.mjs` (`npm run codegen:proto` — manual,
  NOT part of build) shelling to raw `protoc` resolved from the cargo
  vendored `protoc-bin-vendored-<platform>` registry checkout (needs a
  prior cargo fetch), plugin `@bufbuild/protoc-gen-es` ^2.12.0,
  `--es_opt=target=ts,json_types=true,import_extension=ts`. Proto
  sources live in `crates/nimbus-firebase/proto/google/**`. Consumers:
  `internal/protobuf.ts` (namespace re-export choke point) +
  `internal/listen-websocket.ts` (direct imports). CI never generates —
  it builds from the committed gen/.

## Target design (normative)

### CO13 — collapse the triplicated Convex client bodies

1. Two TypeScript mixins (or an equivalent shared-implementation shape
   that ELIMINATES the triplicated method bodies while keeping every
   public overload signature identical):
   - `withConvexInvocationMethods(Base)` — the six methods, declared
     once: Convex-branded overloads + coerce + `super` call.
   - `withConvexLiveQuery(Base)` — `onUpdate` (+
     `assertNamedLiveQueryOptions` gate), applied only to the two live
     clients.
   Composition: `ConvexHttpClient = invocation(NimbusHttpClient)`;
   `ConvexClient = liveQuery(invocation(NimbusClient))`;
   `ConvexReactClient = liveQuery(invocation(NimbusReactClient))`.
   Constructors keep `withConvexDeploymentUrlCheck` and per-class
   options types.
2. The public API surface must be byte-compatible: same exported class
   names, same overloads, same `anyApi` behavior. If the mixin pattern
   cannot express the overloads without weakening them, fall back to
   shared free functions (`convexQuery(superBound, ref, args)`) with
   per-class one-line bodies — the acceptance bar is zero duplicated
   logic, not a specific pattern.
3. Type-level regression: a compile-time assignability test (existing
   selftest/typecheck harness) exercising each class's branded overloads
   (string name, anyApi, real reference) — so a signature regression
   fails typecheck, not runtime.

### CO14 — split the SDK control-plane out of index.ts

1. New `packages/nimbus/src/control-plane/`: `types.ts` (or per-domain
   `services.ts`/`sandboxes.ts`/`sessions.ts` if cleaner — group by
   concept), `client.ts` (`Nimbus` + the sub-manager classes — EXPORT
   the sub-manager classes; unexported-but-instantiated is a smell),
   `discovery.ts` (createDefaultRestClient + credential/endpoint
   discovery helpers).
2. `index.ts` becomes a true thin barrel: re-export the control-plane
   surface plus whatever else `.` exported before. Target under ~100
   lines.
3. Add `"./control-plane": "./src/control-plane/index.ts"` to the
   exports map (mirroring the existing flat-map style, including any
   dist/types dual mapping the other subpaths carry after build).
4. No behavior change; `npm run typecheck`/selftest for the package and
   its consumers (packages/convex, demos) stay green.

### DE16 — stop committing generated protobuf

1. Replace the raw-protoc shell-out with `@bufbuild/buf` (devDep): a
   `buf.gen.yaml` in packages/firebase using the existing
   `protoc-gen-es` plugin with the SAME options
   (target=ts, json_types=true, import_extension=ts), input =
   `crates/nimbus-firebase/proto` (buf can take a directory input; keep
   the proto sources where they are — the Rust crate stays the owner).
   This removes the cargo-registry protoc dependency entirely — pure
   npm.
2. Wire generation into the package `build` script (generate → then
   `build-js-package.mjs firebase`) and into `typecheck`/`test` via a
   shared pre-step so a fresh checkout works with `npm install && npm
   run build`. Keep `codegen:proto` as the standalone alias.
3. `git rm -r packages/firebase/src/gen`, add
   `packages/firebase/src/gen/` to .gitignore. Consumers
   (`internal/protobuf.ts`, `internal/listen-websocket.ts`) keep their
   import paths — generation writes to the same location.
4. Determinism gate: regenerate twice, diff — must be byte-identical.
   Verify the generated output matches what was committed (diff old
   gen/ vs new before deleting; investigate any drift — plugin version
   pin may need updating in lockstep).
5. CI: confirm the root `npm run build --workspaces` path now generates
   (it will, via the build script). If any CI lane consumes
   packages/firebase WITHOUT running its build script, add the generate
   step there — grep .github/workflows for firebase usage and report
   what you found.

## Hard constraints

- `packages/convex` public API byte-compatible (it is the published
  compat surface). `packages/nimbus` may break shape pre-launch but
  keep `.` exporting the same names.
- Do not touch `packages/nimbus-ui` (separate track owns it).
- `lint:capability-boundary` must stay green (convex/firebase are in
  its scope).
- No new runtime dependencies; `@bufbuild/buf` is dev-only.

## Required tests

1. CO13: type-level overload assertions per class; runtime selftest
   exercising one coerced call per class shape (string name + anyApi +
   real ref) against the existing test harness.
2. CO14: selftest imports via both `.` and `./control-plane` resolve
   and typecheck.
3. DE16: double-generate determinism check (scripted in the package,
   runnable in CI); firebase selftest green from a clean tree
   (`git clean -x` the gen dir first to prove generation works).
